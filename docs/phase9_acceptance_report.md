## Final dashboard remediation — 2026-10-14

**Status:** The broken-chart defect is remediated and verified in a live browser. This targeted follow-up does not constitute another full source-to-output pipeline run. It supersedes the earlier dashboard follow-up entries above where they describe broken chart delivery or the ASGI error as unresolved.

### Root cause and fix

- The charts' PNG producers, file paths, names, and bytes were valid. The old dashboard sent them through Streamlit's transient `/media/<id>` image endpoint. A live browser request to that endpoint failed with HTTP 500 and the ASGI RuntimeError. A separate instrumented trace found the associated response-sequence error in Starlette's `FileResponse` for `GET /favicon.png` during a browser disconnect; this was not a chart-file corruption or a bad relative path.
- Reproduction against Starlette 1.8.0 showed the error; a controlled run using Starlette 0.48.0 did not. The locked environment now uses Starlette 1.7.0, constrained in `pyproject.toml` to `>=0.48.0,<1.8.0`. In a live browser on the locked version, favicon responses completed and the ASGI error did not recur. This supports a Starlette `FileResponse` disconnect regression as the trigger; the server may still see ordinary client disconnects, which are not themselves a dashboard defect.
- Dashboard PNG charts now use inline base64 `data:image/png` markup through `st.html`, bypassing the transient media endpoint while retaining the producer's existing chart bytes, labels, and source data. Dynamic Matplotlib charts are serialized to PNG and embedded through the same helper. Missing/unreadable assets remain gracefully unavailable.
- The fairness table showed nonconsecutive retained pandas indexes after filtering. These were display indexes only; the displayed values remained aligned to their subgroup rows. Display tables now reset indexes without changing metrics.
